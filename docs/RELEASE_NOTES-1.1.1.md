# McServerManager 1.1.1

1.1.1 把插件接口版本改成**整数区间**、把插件安装位置**限制在管理器目录内**，
并针对"快速切换页面时 CPU 偏高、界面卡顿"做了一轮性能与解耦改造。

## 下载

| 文件 | 说明 |
| --- | --- |
| `McServerManager-1.1.1-win64.zip` | Windows 10/11 64 位便携版，解压即用（不需要安装 Qt 或 Java） |
| `PLUGIN-SDK.md` | 插件接口说明文档（单独附件，也随包放在 `docs/`） |

> 使用前请先安装并启动 [Docker Desktop](https://www.docker.com/products/docker-desktop/)。

## 插件接口：apiVersion 变成整数区间

* `apiVersion` 是**整数**，每增加一批新接口 `+1`（不再是语义化版本字符串）。
* 管理器维护 `SUPPORTED_MIN_API` 与 `SUPPORTED_MAX_API`（本版都是 `1`）：
  插件的 `apiVersion` 不在区间内会**拒绝加载**，日志与界面会写明原因。
* 破坏性变更时抬高 `SUPPORTED_MIN_API`，旧插件被明确淘汰。
* `minManagerVersion` 只用于**提示用户**（当前管理器更旧时给警告），不参与硬校验。
* 字符串写法 `"1"` 仍然兼容加载，但会提示改成整数。
* `mcsm-cli plugin api` 现在额外输出接口区间、版本策略与安全策略，方便脚本自检。

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "apiVersion": 1,
  "minManagerVersion": "1.1.1"
}
```

## 安全：插件只允许装在管理器目录内

* 安装目标必须在 `<数据目录>/plugins/` 之内，越界直接拒绝（`UNSAFE_PLUGIN_PATH`）。
* 解压前扫描压缩包条目：绝对路径、盘符、UNC、`..` 跳出目录一律拒绝（zip-slip 防护）；
  解压后再逐个校验落盘路径仍在插件目录内，并拒绝符号链接。
* 插件的 `frontend` / `backend` / `web` 入口与 `web.service` 必须是包内相对路径；
  后端入口和前端 `mcsm.include()` 都会展开真实路径再校验，避免通过 `..` 或链接执行外部程序。

## 性能：快速切换页面不再卡

同机实测（12 逻辑核，快速轮切 7 个页面，进程 CPU 占用）：

| 场景 | 1.1.0 | 1.1.1 |
| --- | --- | --- |
| 空闲 | 0.29% | **0.03%** |
| 120ms 间隔轮切（53 次） | 2.20% | **1.15%** |
| 60ms 间隔轮切（95 次） | 2.91% | **1.76%** |

做法：

* 切页不再对整页做 `grab()` 快照（那是每次切换最贵的一步），并且**连点时直接瞬切**，不再逐帧跑动画；
* 窗口背景（渐变 + 柔光）改成缓存位图，只在窗口尺寸 / 主题变化时重绘；
* 页面激活时的刷新统一**节流**（`doctor` 4 秒、列表/详情 1.5–2.5 秒），背景页面不再因为轮询而重建控件；
* 修掉设置页每次进入都会重复连接 `environmentChanged` 的信号泄漏；
* 服务器列表内容未变化时不再触发模型信号，轮询不再引起全界面重绘；
* 离开控制台页 5 秒后自动停止 `docker logs --follow`。

## 解耦：一条卡住不会拖死全部

* 插件前端脚本加看门狗（加载 2500ms / 单次事件 1000ms），超时强制中断并临时停用该插件；
* 插件读取服务器列表改为缓存快照，不再同步等待后端进程（旧版本一个插件就能卡住整个窗口）；
* 后端异步请求加 15 分钟看门狗，杜绝"命令卡住 → 回调永不返回 → 功能永久卡死"；
* 定时备份守护进程带 `--parent-pid`，管理器被强杀后自动退出，不再残留孤儿进程。

## 升级说明

* 直接从 1.1.0 覆盖升级即可，数据目录与服务器不受影响。
* 自己写了插件的话：把 `plugin.json` 里的 `apiVersion` 由 `"1"` 改成 `1`（整数），
  可以再加一行 `minManagerVersion` 提示所需的管理器版本。
